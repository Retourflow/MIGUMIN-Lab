---

这次是从 `CanvasGroup` 开始往下顺出来的一些东西。

一开始只是看到一句话：

> Unity 的单独 UI 物体没有一个很方便的统一不透明度控制，通常要改 `Color` 里的 Alpha。`CanvasGroup` 可以统一控制一组 UI 的透明度。

本来觉得这只是一个 UI 组件的问题，后来才发现它其实会一路牵扯到 Alpha 混合、Spine、Live2D、3D 透明渲染，甚至角色切换为什么经常不用普通淡出。

---

## CanvasGroup 到底解决了什么

普通的 `Image`、`Text` 这类 UI，本身都有自己的颜色：

```text
Color = R G B A
```

其中 `A` 就是 Alpha。

```text
1   = 完全不透明
0.5 = 半透明
0   = 完全透明
```

如果只控制一张图片，直接改它自己的 Alpha 就可以。

但如果一个 UI 是：

```text
Panel
├── Background
├── Icon
├── Text
├── Button
└── Decoration
```

那一个个去改就很麻烦。

`CanvasGroup` 的方便之处就在这里：

```csharp
canvasGroup.alpha = 0.5f;
```

它可以让下面这一组 UI 一起变淡。

但这里有个很容易误解的地方。

`CanvasGroup` 并不是先把整组 UI 合成成一张图片，然后再让这一整张图片变透明。

下面这些东西实际上还是独立存在、独立渲染的：

```text
Background
Icon
Text
Button
Decoration
```

只是它们都会受到 `CanvasGroup.alpha` 的影响。

---

## 刮刮乐彩票这个例子最好理解

假设一个彩票 UI 是这样叠的：

```text
最上面：银色刮刮层
下面：中奖内容
最后面：背景
```

正常的时候银色刮刮层是不透明的，所以中奖内容看不到。

也就是：

```text
银色层
████████████

中奖内容
  1000 元
```

上面的银色层把下面盖住了。

但如果整个页面开始淡出：

```text
CanvasGroup.alpha = 0.5
```

这时候并不是“彩票这一整张画面变成 50%”。

而是：

```text
银色刮刮层 → 变成半透明
中奖内容     → 也变成半透明
```

问题就出来了。

银色层以前能完全盖住中奖内容，现在它自己变成半透明以后，就像一张半透明塑料片。

那下面的内容自然就会透出来。

中奖内容虽然自己也变淡了，但它并没有消失，所以还是能看到。

这也是我一开始最容易想错的地方：

> 两层一起透明，不代表两层就像一个整体一起消失。

它们只是“各自变透明了”。

---

## 透明不是消失

这个其实是理解后面所有问题的关键。

透明更接近：

```text
让我后面的东西参与到最终画面里
```

而不是：

```text
我自己单纯地越来越看不见
```

所以只要前面的图层开始半透明，后面的图层就有机会显出来。

---

## 为什么颜色还会变深

多层图片一起变半透明以后，不只是会互相透出来，还会互相混色。

比如白色背景上有一层 50% 透明的黑色。

看起来会变成灰色。

如果再在上面叠一层 50% 透明的黑色，它不是还是同样的灰，而是会继续变深。

因为第二层是在“第一层已经混合后的结果”上继续做 Alpha 混合。

所以多层深色素材重叠的时候，颜色就很容易越来越重。

这也是为什么：

```text
眼睛
眉毛
阴影
头发
嘴巴内部
```

这些比较深或者比较鲜艳的颜色，在角色淡出的过程中尤其容易显得奇怪。

---

# Spine / Live2D 为什么容易中招

Spine 和 Live2D 看起来是一个完整人物，但实际上一般都是很多素材拼起来的。

大概会有：

```text
后发
脸
前发
刘海
眉毛
眼白
瞳孔
眼皮
嘴唇
口腔
牙齿
衣服
手
阴影
高光
```

然后靠骨骼、网格变形、参数和遮罩来动。

这一点和 Live2D 特别像。

眨眼不是“整张图换掉”，而是眼睛相关的部件在动。

张嘴也不是一张完整人物图片在切换，而是：

```text
嘴唇
口腔
牙齿
舌头
```

这些东西分别在变化。

所以从人的角度看：

```text
这是一个角色
```

但从渲染的角度看：

```text
这是很多层图片
```

---

## 角色淡出的时候会发生什么

正常情况下，这些图层之间有稳定的遮挡关系。

前面的东西可以挡住后面的东西。

比如：

```text
刘海挡住后发
眼皮挡住一部分眼球
脸部区域压住后面的素材
嘴部遮罩限制口腔显示范围
```

但如果直接让整个人物所有部分一起 Alpha 下降：

```text
后发 → 半透明
脸 → 半透明
刘海 → 半透明
眼睛 → 半透明
嘴巴 → 半透明
阴影 → 半透明
```

那以前能挡住后面的层，现在就挡不严了。

原本不该看见的东西可能透出来。

而且这些透出来的东西又会继续和前面的图层混色。

所以就可能出现：

```text
眼睛突然变得很黑
嘴部的红色异常明显
脸部发灰
头发和脸重叠的地方发脏
一些隐藏素材突然显出来
```

有些游戏里会出现那种淡出的一瞬间“脸突然像鬼一样”的情况，本质上就是这个。

---

## 我之前有一个想法需要修正

一开始我想成：

```text
脸在最前面
眼睛嘴巴在脸后面
```

但实际的角色分层并不一定是这样。

很多时候可能更像：

```text
最前：
眼睛 / 眉毛 / 嘴巴细节

然后：
刘海 / 前发

再然后：
脸

后面：
后发
```

所以不能简单地说：

> “脸一透明，眼睛从后面露出来。”

真正的问题是：

> 角色内部有很多互相重叠、互相遮挡的独立图层，一起半透明以后，原来的遮挡关系失效了一部分。

这个说法更准确。

---

## 脸和头发一起变淡为什么可能偏黑

比如：

```text
后面是深色头发
前面是脸
```

正常时脸是不透明的。

所以：

```text
深色头发
+
不透明的脸
=
只看到正常肤色
```

但如果脸也变成半透明：

```text
半透明深色头发
+
半透明脸
```

头发的深色就可能透进脸里面。

于是脸的某些区域看起来会：

```text
偏灰
偏黑
发脏
```

如果同一区域还有阴影、刘海、眼睛等东西一起叠，就更明显。

# 渲染顺序

一般可以先简单理解成：

> 后面的东西先画，前面的东西后画。

比如：

```text
后发
脸
前发
```

大致就是先画后发，再画脸，再画前发。

后画的东西盖在前面已经画好的东西上。

淡出的时候，这个绘制顺序通常没有变。

变的是：

```text
前面的东西不再完全不透明
```

所以它虽然还是后画、还是在前面，但已经不能像以前那样完全挡住后面了。

这点很重要。

问题不是：

```text
图层顺序乱了
```

而是：

```text
遮挡能力变弱了
```

---

# RenderTexture 为什么能解决

`RenderTexture` 的思路其实很直观。

先把人物正常渲染完整：

```text
后发
脸
眼睛
嘴巴
刘海
衣服
……
```

所有内部的前后关系、遮挡、混色先处理完。

然后得到最终的一张画面。

可以把它理解成：

```text
先给角色拍一张实时照片
```

之后再让这张“照片”淡出。

这样就不是：

```text
脸单独透明
眼睛单独透明
头发单独透明
嘴巴单独透明
```

而是：

```text
最终角色画面整体透明
```

这样内部图层已经被压成最终结果，不会在淡出的过程中重新互相透出来。

---

## 两种做法的区别

直接淡出多层角色：

```text
脸 × 0.5
头发 × 0.5
眼睛 × 0.5
嘴巴 × 0.5

然后继续叠
```

RenderTexture：

```text
脸 + 头发 + 眼睛 + 嘴巴
↓
先正常渲染
↓
得到最终角色画面
↓
最终画面 × 0.5
```

这两个结果不是一回事。

---

# 3D 模型也会有类似问题

3D 人物虽然不是多张二维图片，但本质上也有很多前后结构。

比如：

```text
头发
脸
眼球
牙齿
舌头
身体
衣服
身体背面
```

正常情况下，大多数角色材质是不透明的。

GPU 会通过深度测试判断谁在前谁在后。

所以：

```text
脸挡住眼球的一部分
衣服挡住身体
身体前面挡住身体后面
```

都没有问题。

但如果简单粗暴地把整个 3D 角色所有材质都改成半透明：

```text
脸 50%
眼球 50%
牙齿 50%
衣服 50%
身体 50%
```

那就可能通过脸看到眼球、牙齿，甚至后面的结构。

通过衣服也可能看到身体。

最后就会有一种“玻璃人”的感觉。

---

## 3D 透明还有额外问题

3D 的透明排序本身就很麻烦。

因为三角面不是简单的一层一层平铺，而是互相穿插的。

比如：

```text
前发
脸
侧发
后发
衣服
身体
```

这些东西的空间关系很复杂。

半透明以后，GPU 不一定总能把所有透明面按照完美的前后顺序处理。

所以有时候还会看到：

```text
后发跑到脸前面
透明面突然跳层
角色内部结构显示异常
```

这比 2D 多层透明还更麻烦。

---

# 为什么很多游戏角色切换不直接用普通淡出

以前看到游戏角色切换，经常会觉得：

```text
为什么不直接 Alpha 1 → 0？
```

现在就能理解了。

对于 Spine / Live2D：

```text
可能层层透出
可能颜色变深
可能出现鬼脸
```

对于 3D：

```text
可能看到眼球、牙齿、身体内部
可能有透明排序问题
```

所以实际项目里更常见的是别的方案。

---

## 特效遮挡

比如：

```text
角色
↓
闪光 / 烟雾 / 粒子
↓
在特效遮住的时候换角色
↓
特效散掉
```

其实就是把切换过程藏起来。

---

## Dissolve

溶解不是把整个人全部改成半透明。

它更像：

```text
这一块还存在
那一块已经消失
```

也就是像素要么显示，要么被裁掉。

所以剩下来的区域还能保持正常的材质效果。

不会整个角色一起变成玻璃。

---

## Dither Fade

Dither 也是类似。

它会让越来越多像素不显示。

远看像角色慢慢淡出，但单个像素本身并没有一起变成半透明。

---

# 溶解为什么还要做得像蒙版转场

如果只是随机删像素，会很奇怪。

看起来可能不是角色在传送，而是：

```text
贴图坏了
模型缺块了
显卡炸了
```

所以溶解一般会有一个明确的方向或者蒙版。

比如：

```text
从脚到头
从左到右
从中心向外
```

或者使用噪声图。

噪声图里不同灰度决定：

```text
哪里先消失
哪里后消失
```

随着阈值变化，消失区域慢慢推进。

这样就会更像一种“转场”。

---

## 溶解边缘一般还会加东西

单纯裁像素还是比较生硬。

所以经常会在消失边缘加：

```text
发光
火焰
电流
粒子
烟雾
像素块
扭曲
```

这样玩家看到的就不是：

```text
角色缺了一块
```

而是：

```text
角色正在传送 / 分解 / 数据化
```

同样是把像素删掉，美术包装不同，感觉完全不一样。

---

# 这次真正学到的东西

我原本只是想知道 CanvasGroup 为什么会让 Spine 淡出出现问题。

后来发现关键其实不是 CanvasGroup，而是：

```text
多层图片一起半透明
```

这件事本身。

只要一个画面内部有很多前后叠放的元素，而这些元素原本依赖“不透明”来互相遮挡，那么一起改成半透明以后，就可能：

```text
后层透出来
颜色继续混合
局部变深
隐藏结构显现
```

所以：

```text
多层一起透明
```

和：

```text
先合成，再整体透明
```

是完全不同的两件事。

这也直接解释了：

```text
CanvasGroup 淡出为什么有时会穿帮
Spine / Live2D 为什么容易出现鬼脸
3D 为什么不适合简单全材质透明淡出
RenderTexture 为什么有效
Dissolve / Dither 为什么常用于角色消失
```
